# 同桌 · 局域网斗地主

一个真正能运行的三人斗地主第一版。前端 **Vue 3 + TypeScript + Vite**，后端 **Node.js + TypeScript + ws**。不用数据库、账号或外部素材服务，房间和牌局保存在服务器内存。

## 1. 两条命令启动

在此项目目录执行：

```sh
npm install
npm run dev
```

- 电脑打开 `http://localhost:5173`。
- 手机/其他电脑连接同一 Wi-Fi，打开启动终端显示的 **Wi-Fi / 以太网 IPv4 地址**，例如 `http://192.168.100.7:5173`。
- 房主输入昵称并创建房间，点击「邀请朋友」复制链接或分享 6 位房间号。
- 另外两人加入同一房间，三人点击「准备好了」后自动发牌。
- 保持启动服务的终端与电脑运行。按 `Ctrl+C` 可停止前后端。

**其他设备不能用 localhost 或 127.0.0.1 访问你的电脑。** IP 可能随网络或 DHCP 改变，重启时以终端输出为准。

### 当前环境的 Node 兼容

项目包含开发依赖 `node@22.23.3`，`npm run` 会优先使用项目内的 Node 22，不修改全局 Node、Shell 配置或其他项目。首次安装需要联网并下载当前平台的 Node 二进制。

当前默认 Node 16 的环境安装时可能显示 `EBADENGINE` 警告；`postinstall` 会使用项目内 Node 22 补齐 Vite 的原生依赖，实际运行使用 Node 22。已在该环境验证安装、启动、构建和测试。不要加 `--ignore-scripts` 或 `--omit=dev`：这会跳过本地运行时安装/补全。若本机启用了 `engine-strict`，请先使用 Node 22.12+ 安装，推荐 Node 22 LTS。

## 3. 第一版规则（以此为准）

### 叫抢地主

随机一人先叫，依照座位顺序，每人只有一次叫/抢机会；**最后选择叫/抢的人是地主**。三人全部不要则重新发牌。这是简化叫抢模式，不含回抢、三分叫分、明牌、加倍和积分结算。

### 牌型

| 牌型             | 条件 / 例子                              |
| ---------------- | ---------------------------------------- |
| 单张、对子、三张 | 3；44；555                               |
| 三带一、三带二   | 3334；33344                              |
| 顺子             | 至少 5 张连续单牌，最高到 A              |
| 连对             | 至少 3 对连续对子，最高到 A              |
| 飞机             | 至少 2 组连续三张，最高到 A              |
| 飞机带单         | 每组三张带一张，单翅膀允许组成对子       |
| 飞机带对         | 每组三张带一对，翅膀必须是不同点数的对子 |
| 四带二           | 四张同点数 + 两张，允许带一对            |
| 四带两对         | 四张同点数 + 两种不同点数的对子          |
| 炸弹             | 四张同点数                               |
| 王炸             | 大王 + 小王                              |

飞机主体必须是完整三张，翅膀不得与主体同点数。顺子、连对、飞机主体都不能包含 2 或王。本项目不采用「四张拆三张并把第四张当同点数翅膀」规则；两个炸弹也不当作四带两对。

普通牌必须同牌型、同张数、同连续长度，用主体点数比较。点数顺序：`3 < … < 10 < J < Q < K < A < 2 < 小王 < 大王`。炸弹压普通牌型，王炸最大。连续两人不出，最后出牌者重新领出，新一轮不能直接不出。

地主先出完手牌则地主胜；任一农民先出完则两位农民一起胜。提示只给出一手合法的基础建议，不是策略 AI。

## 4. 网络配置

默认只需让其他设备访问前端端口 **5173**。Vite 同源代理 `/ws` 和 `/api` 到后端 **3001**，因此手机无需单独配置后端地址，也不需要修改源码中的 IP。

```
手机 / 电脑
    │ http://电脑IP:5173
    ▼
Vite :5173（0.0.0.0）
    ├── Vue 页面
    ├── /api/* ── HTTP 代理 ──┐
    └── /ws ── WebSocket ─────┤
                              ▼
                      Node :3001（0.0.0.0）
                              │
                      房间 / 规则 / 私有手牌
```

自定义端口（macOS / Linux）：

```sh
PORT=3002 FRONTEND_PORT=5174 npm run dev
```

PowerShell：

```powershell
$env:PORT="3002"
$env:FRONTEND_PORT="5174"
npm run dev
```

环境变量直接从终端设置，本版本未配置 `.env` 文件自动加载。

### 无法连接时

1. 确认三台设备在同一 Wi-Fi / 子网，电脑没有休眠、终端没有关闭。
2. 地址要有 `http://` 和端口。手机不使用 `localhost`。
3. 多网卡情况下，在「邀请朋友」中选择 Wi-Fi/以太网 IP，不选 VPN、虚拟机或隧道地址。
4. 允许系统防火墙接收 Node 的局域网连接。不建议关闭整个防火墙。
5. 关闭会影响局域网路由的 VPN；访客 Wi-Fi 或开启 AP / 客户端隔离的网络可能禁止互访。
6. 端口被占用会报错并停止启动；请换端口或先停止原来的服务。
7. 主机访问自身 IP 成功并不保证手机能穿过路由器隔离。仍需用真实手机验证网络路径。

### 协议要点

客户端消息含 `type` 和唯一 `requestId`。服务端返回 `ack`，成功改变状态后向该房间的每名玩家单独发送 `state`。前端只展示快照，不自行决定结果。

- `create { name }` / `join { name, code }` → 返回随机会话 token。
- `resume { token }` → 恢复同一个座位和手牌。
- `ready { ready }` / `bid { bid }` / `play { cardIds }` / `pass`。
- `rematch` / `leave`。
- `GET /api/health` / `GET /api/network`。

客户端不能提交玩家 ID 来替别人操作；身份只由 WebSocket 已绑定的服务端会话决定。Token 保存在当前标签页的 `sessionStorage`，因此刷新能恢复，独立新开三个标签页可做本机三人测试。不要直接「复制标签页」来模拟不同玩家，因为浏览器可能复制 `sessionStorage`；请新建空白标签再输入地址。

## 7. 边界与安全

这是可信局域网的第一版，不是公网上线服务：

- 不含数据库、账号认证、房间密码、旁观、机器人、聊天或排行榜。
- 重启后端会清空所有房间和对局；修改后端源码需手动重启，前端支持热更新。
- 不保存历史战绩，无真实金钱/下注/支付。
- 断线保留 2 分钟；主动离开立即释放座位。6 小时没有游戏操作的房间会清理。
- 默认为 HTTP/WS，不加密，不应在不可信网络传播会话 token。
- 同源检查、限流和私有手牌分发不等同于生产安全。**不要把开发端口直接映射到公网。**
- 依赖安装需要互联网；安装后游戏运行不依赖外网服务。
